# 首版监控规则

- 使用 Next.js 和 daisyUI 构建控制台。任意 GitHub 用户登录后可查看监控和故障记录。部署时指定的 GitHub 管理员可修改配置。
- 同一服务可绑定多个监控项。每项独立判断状态和触发通知，任一监控项异常时，服务总览显示异常。
- 主动探测仅覆盖公网 HTTP(S) 目标，每 30 秒发送一次请求。默认接受 `2xx`，并允许为监控项指定预期状态码。非预期状态码、网络错误和请求超时均计为失败。连续两次失败触发故障，下一次成功触发恢复。
- 被动接入由第三方服务发起 WebSocket 连接，每 5 秒发送一次应用心跳。监控项初始处于等待接入，首次有效上报后开始计时。平台按接收时间计算心跳是否满 15 秒未更新，连接断开后客户端自动重连。需要独立告警的实例各自使用独立监控项。
- 被动端显式上报异常时立即触发故障，并保持异常直到收到显式健康上报。普通心跳可恢复仅由心跳超时引起的故障。
- 每个监控项可绑定多个 Bark、Webhook 和邮件渠道。进入异常与恢复时各触发一次通知，持续异常期间默认不重复通知。每个渠道独立重试并记录投递结果。
- 首版按 100 个监控项设计。主动探测明细保留 7 天，已结束的故障与已完成的投递记录保留 90 天。应用心跳更新最近接收时间，平台记录被动监控的状态变化。
